# 🔐 Задание 4. Оценка узких мест при миграции

## 🗂️ Классификация узких мест

| Категория                  | Проблемы                                                               |
| -------------------------- | ---------------------------------------------------------------------- |
| 🏗️ Инфраструктура          | Один сервер, отсутствие отказоустойчивости, локальное размещение       |
| 💾 Программное обеспечение | Excel и 1С в файловом режиме, нет автоматизации, CI/CD                 |
| 🔌 Интеграции              | Сложность с API, устаревшие форматы, проблемы с миграцией              |
| 👥 Персонал                | Недостаток квалификаций, перегрузка IT, отсутствие DevOps              |
| 🔁 Процессы                | Нет стратегии миграции, отсутствует тестовая среда, нет rollback-плана |
| 🔒 Безопасность            | Нет шифрования, IAM, аудита и мониторинга доступа                      |

## ✅ Рекомендации и меры

| Мера                                                      | Приоритет  | Категория               |
| --------------------------------------------------------- | ---------- | ----------------------- |
| Перенос в облако (IaaS/PaaS), отказоустойчивость          | 🔴 Высокий | Инфраструктура          |
| Внедрение CI/CD, автотестов, GitOps                       | 🟡 Средний | Программное обеспечение |
| API-first подход и миграция от Excel к REST               | 🔴 Высокий | Интеграции              |
| Найм DevOps-инженера, обучение персонала                  | 🔴 Высокий | Персонал                |
| Стратегия миграции, создание staging-среды, rollback-план | 🔴 Высокий | Процессы                |
| Шифрование TLS/AES, внедрение IAM, SIEM, DLP              | 🔴 Высокий | Безопасность            |

---

## 📋 Отчёт по компонентам и рискам

| Компонент             | Риск                          | Рекомендация                             |
| --------------------- | ----------------------------- | ---------------------------------------- |
| 🧾 1С, Excel          | Локальный режим, нет API      | Миграция в облачные серверные решения    |
| 📄 PDF / JPG карты    | Невалидируемые форматы        | Конвертация в структуру + OCR + хранение |
| 🖥️ Сервер Windows     | Отсутствие отказоустойчивости | Внедрение репликации или кластеризации   |
| 📡 Нет IAM            | Неразграниченный доступ       | RBAC/ABAC + централизованный контроль    |
| 🚫 Нет CI/CD          | Ошибки при релизах, задержки  | Внедрить GitLab CI, автотесты            |
| 🧪 Нет тестовой среды | Риски продакшен-сбоев         | Staging-среда + QA                       |

---

## 🧱 Инфраструктурные узкие места

- Сервер в офисе → потенциальная точка отказа
- Нет масштабируемости → риски при росте числа клиентов
- Нет изоляции окружений → продакшен и тест смешиваются

---

## 🔐 Безопасность

| Уязвимость               | Потенциальные последствия         | Рекомендации                               |
| ------------------------ | --------------------------------- | ------------------------------------------ |
| Данные не зашифрованы    | Утечка PII, SPII                  | TLS 1.3, AES-256                           |
| Нет контроля доступа     | Любой может получить любые данные | RBAC/ABAC, IAM                             |
| Нет мониторинга и аудита | Нарушения остаются незамеченными  | SIEM-система, Audit Logging                |
| Нет тегирования данных   | Нельзя понять, что защищать и как | Apache Atlas, Data Catalog + Policy Engine |

---

## 🎯 Заключение

Переход «Медикаменте» на новую архитектуру требует:

- Миграции в облачную и масштабируемую инфраструктуру
- Внедрения CI/CD, контроля версий и процессов DevOps
- Усиления команды: DevOps-инженер, архитектор, QA
- Централизации безопасности: IAM, шифрование, мониторинг
- Полной стратегии поэтапной миграции с откатами и тестированием

📈 Это обеспечит рост компании без потери доверия клиентов, с соблюдением законодательства и технологической зрелостью.
